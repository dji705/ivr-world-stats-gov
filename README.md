# מערכת מידע טלפונית — פרטי רכב, תו נכה ומפלס הכינרת

מאגר זה מפעיל API ב־Vercel עבור מערכת IVR של ימות המשיח.

- **מאגר GitHub:** https://github.com/dji705/ivr-world-stats-gov
- **כתובת ה־API של ימות:** https://ivr-world-stats-gov.vercel.app/api/yemot
- **מקור הנתונים:** data.gov.il
- **שירותים:** פרטי רכב, בדיקת תו נכה לרכב, מפלס הכינרת.

> חשוב: קובץ זה מתעד את מבנה הפרויקט ואת מזהי מאגרי הנתונים. מפת השלוחות המוצעת בהמשך היא תכנון לוגי; יש ליצור ולהגדיר שלוחות נפרדות במערכת ימות בפועל אם רוצים תהליך קלט רב־שלבי. אין להניח שהשלוחות כבר נוצרו בחשבון ימות.

## 1. הגדרת שלוחת API בימות המשיח

בקובץ ext.ini של שלוחת ה־API:

    type=api
    api_link=https://ivr-world-stats-gov.vercel.app/api/yemot

## 2. מפת תפריט השלוחות — תכנון מומלץ

המטרה היא להפריד בין בחירת השירות לבין הקלדת מספר הרכב, במקום לחבר את ספרת השירות ומספר הרכב לקלט אחד.

    שלוחה ראשית
    ├── 1 — פרטי רכב
    │   └── שלוחת קלט מספר רישוי
    │       └── אישור באמצעות # → קריאה ל־API וחזרה לתוצאות
    ├── 2 — בדיקת תו נכה
    │   └── שלוחת קלט מספר רישוי
    │       └── אישור באמצעות # → קריאה ל־API וחזרה לתוצאות
    └── 3 — מפלס הכינרת
        └── קריאת נתון עדכני מה־API

### זרימת שיחה רצויה

1. המערכת משמיעה את התפריט הראשי.
2. המתקשר בוחר שירות באמצעות מקש יחיד.
3. בבדיקת רכב או תו נכה, המערכת מבקשת להקליד את מספר הרישוי בשלב נפרד.
4. המתקשר מקליד את הספרות ומסיים ב־#.
5. המערכת בודקת שהמספר תקין, פונה למקור הנתונים ומקריאה את התוצאה.
6. אפשר להגדיר את * לביטול או חזרה לתפריט רק לאחר שמוודאים שהגדרת השלוחה תומכת בכך.

**הערה לגבי הקלט:** טלפון כשר אינו משנה את פרוטוקול הקלט של שרת ה־IVR. המערכת הטלפונית מקבלת את ספרות ה־DTMF שהמתקשר מקיש. כדי לקבל מספר רכב בשלב נפרד צריך להגדיר זרימת שלוחות או מצב קלט נפרד בימות ולשמור/להעביר את בחירת השירות בין השלבים. הקוד הנוכחי של /api/yemot עדיין לא מהווה לבדו הוכחה שזרימה רב־שלבית כזו הוגדרה ונבדקה בחשבון ימות.

## 4. נתיבי API

| נתיב | תפקיד |
|---|---|
| GET /api/yemot | תגובת טקסט בפורמט של ימות המשיח |
| GET /api/vehicle?plate=1234567 | פרטי רכב ב־JSON |
| GET /api/disability-badge?plate=1234567 | בדיקת תו נכה ב־JSON |
| GET /api/kinneret | מפלס הכינרת ב־JSON |

מספר הרישוי חייב להכיל בין 5 ל־9 ספרות. תוצאות תלויות בזמינות ובתוכן של מקור הנתונים הממשלתי.

## 5. שדות פרטי רכב

הקוד יכול להקריא שדות זמינים מתוך הרשומה, ובהם:

- מספר רישוי
- קוד יצרן וסוג הדגם
- יצרן הרכב ושם הדגם
- רמת גימור ורמת אבזור בטיחותי
- דרגת זיהום אוויר
- שנת ייצור ודגם מנוע
- תאריך טסט אחרון ותוקף רישיון
- סוג בעלות ומספר שלדה
- צבע הרכב
- מידות צמיגים קדמיים ואחוריים
- סוג דלק
- תאריך עלייה לכביש ושם מסחרי

רק שדות שמוחזרים בפועל ממקור הנתונים יופיעו בתוצאה.

## 6. קבצים חשובים בפרויקט

- api/yemot.js — נקודת הכניסה של ימות המשיח, טיפול בקלט והקראת תוצאות.
- api/_lib/data.js — מזהי המאגרים, שדות הרכב, בקשות למקור הנתונים ובדיקת מספר רישוי.
- api/_lib/yemot.js — עיצוב מספרים, פיצול טקסט למקטעי הקראה וחישוב שלוחת האב.
- README.md — תיעוד הפרויקט והגדרות השלוחות.

## 7. בדיקה ופריסה

1. ודאו שהפרויקט ב־Vercel מחובר למאגר GitHub הנכון.
2. ודאו שהפריסה האחרונה הסתיימה בהצלחה.
3. בדקו בדפדפן את /api/kinneret, את /api/vehicle?plate=1234567 ואת /api/yemot.
4. בצעו שיחת ניסיון אמיתית דרך ימות כדי לבדוק את אופן קבלת ההקשות, את סיום הקלט באמצעות #, את החזרה לתפריט ואת ההקראה בעברית.
5. אל תחשיבו את תהליך הקלט הרב־שלבי כתקין עד שנבדק בשיחה אמיתית.
